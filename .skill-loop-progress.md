## Baseline and decision model

- Source state: `main`, clean, equal to `origin/main` at campaign start.
- Host state: macOS load average `110.35 81.13 61.93`; local timing and heavy
  compilation are contaminated, so build/test work uses RCH and performance
  claims require a remote-host fingerprint.
- Binary state: the local `target/release/dcg` is a foreign Linux artifact and
  cannot serve as a macOS runtime baseline; a current remote release build was
  queued before optimization.
- Safety states: `{safe, destructive, indeterminate, infrastructure_fault}`.
- Bridge actions: `{allow, block, fail_open_with_diagnostic}`.
- Asymmetric losses (relative units): destructive false allow `1000`;
  indeterminate false allow `500`; safe false block `5`; safe infrastructure
  fail-open `1`; silent infrastructure failure `25`. Existing public policy is
  preserved: dcg decisions `deny`/`ask`/`indeterminate` block, while an absent or
  unrunnable dcg binary fails open visibly.
- Proof ladder: Tier A golden/contract invariants for every pass; Tier B
  property/metamorphic tests for parsers and path state machines; bounded model
  exploration for lifecycle/protocol state machines where it has positive EV.
- Optimization acceptance: one lever per pass, measured hotspot or concrete
  correctness risk, semantic-isomorphism argument, explicit fallback, and no
  material p99 regression. Clever mechanisms that cannot clear those gates are
  rejected rather than shipped.
